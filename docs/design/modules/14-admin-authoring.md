# 后台内容创作与发布模块设计

## 1. 模块职责

定义后台内容的草稿、版本、自动保存、校验、预览和发布流程，把文章与时间轴的写入统一到一致的创作与发布契约，并保证发布事务、缓存失效和审计的一致性。消费方包括文章书写页、后台时间轴管理、后台仪表盘与后台设置。

本模块不定义各页面的布局；页面编排见对应页面文档。

## 2. 内容来源与契约

- 文件型内容：`content/posts/*.mdx` 为真实来源，后台只读索引，构建期生成。
- 数据库型内容：启用在线创作后，`posts` 保存正文与状态；同一内容不得同时存在两个不一致来源。
- 读取契约由 `PostRepository` 统一，文件源与数据库源共享接口，页面不感知来源。
- 写入契约由受保护 Server Action 提供，统一 `requireAdmin()` 与 Zod 校验。

## 3. 状态机

```text
draft -> published -> archived
archived -> published（允许恢复）
draft -> archived（放弃草稿）
```

- 只有 `published` 对匿名访客可读。
- 发布写入 `published_at` 并产生 activity event。
- 编辑已发布内容保留发布状态并更新 `updated_at`。
- 删除优先 archive/soft delete；永久删除为独立高风险动作。

## 4. 草稿与版本

- 自动保存只写草稿版本，间隔 15–30 秒或失焦触发，不自动发布。
- 每次保存形成版本记录，支持查看最近版本并回滚。
- 会话过期或网络失败时，客户端保留本地临时草稿；恢复后提示合并，不静默丢弃。
- 草稿与已发布内容分离存储或通过状态字段区分，预览不进入公共缓存。

## 5. 校验规则

发布前校验在服务端执行，客户端即时校验只作提示：

- 必填字段：标题、slug、摘要、发布时间（或立即发布）。
- 封面存在则 alt 必填。
- slug 规范化且唯一；发布后修改 slug 必须规划重定向。
- 内部链接存在、外部链接协议白名单（http/https/mailto），拒绝 `javascript:`/`data:`。
- MDX 编译通过、组件在允许列表、图片路径存在。
- 时间轴节点：内容与发生时间必填，类型为有效枚举。

## 6. 预览

- 预览在与公开内容一致的白名单管线下渲染。
- 预览受管理员会话或短期 token 保护，`noindex`，不写入日志或公开 referrer。
- 预览失败不阻断编辑，显示可读错误。

## 7. 发布事务与缓存失效

1. 校验通过并确认版本（乐观锁）。
2. 事务内写入正文与状态、写 `activity_events`/审计。
3. 提交成功后按内容类型失效缓存 tag：
   - 文章：`post:{slug}`、`posts`、`home`、`tag:*`/`category:*`、`rss`、`sitemap`。
   - 时间轴：`timeline-item:{id}`、`timeline`、`home`、`stats-public`。
4. 外部构建失败记录状态并可重试，不把未提交内容标记成功。

## 8. 并发与一致性

- 使用 `updated_at`/version 乐观锁；冲突时阻止覆盖并要求重新加载或合并。
- 不允许半完成状态：数据库已发布而正文未保存视为失败。
- 自动保存与手动保存串行化，避免交叉写入。

## 9. 审计与安全

- 记录创建、更新、发布、归档、删除的 actor、时间、目标与结果。
- 上传与自定义组件均服务端校验；输出转义防 XSS。
- service role 与 salt 只在 server-only 模块使用，不下发客户端。

## 10. 验收标准

- 草稿、版本、自动保存与恢复按契约工作，不自动发布。
- 发布前校验覆盖 frontmatter、MDX、图片、链接与 slug。
- 保存/发布失败不丢失正文，并发编辑不静默覆盖。
- 发布后相关页面与 sitemap/RSS 按失效矩阵更新。
- 关键操作有审计记录，敏感字段不外泄。

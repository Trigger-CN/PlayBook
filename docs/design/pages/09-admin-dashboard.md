# 后台仪表盘设计

## 1. 页面目标

后台仪表盘提供管理员登录后的工作摘要和明确待办，优先回答“现在需要处理什么”，而不是复制公开统计页。

- 路由：`/admin`
- 阶段：Phase 8
- 用户：管理员

## 2. 页面布局设计

### 2.1 桌面端

1. 后台外壳与页面标题、数据更新时间。
2. 待办条：待审核评论、草稿文章、近期失败任务。
3. 核心摘要：今日/近 7 日浏览、互动、内容发布数。
4. 双栏工作区：最近内容变更、最近评论。
5. 活动日志和快捷操作：新建时间轴、审核评论、查看站点。

页面使用紧凑网格和列表。摘要指标可以是卡片，但不在卡片中再嵌套操作卡。危险操作不出现在仪表盘。

### 2.2 移动端

- 待办和摘要单列/两列。
- 最近内容、评论纵向排列。
- 快捷操作自动换行，保持立体按钮触控面积。

## 3. 功能设计

- 待审核评论计数链接到 `/admin/comments?status=pending`。
- 草稿文章计数链接到 `/admin/posts?status=draft`。
- 最近内容显示类型、标题、状态、更新时间和编辑入口。
- 最近评论显示作者、目标、摘要、时间和审核入口，不展示完整邮箱/IP。
- 活动日志记录管理员和系统事件，支持进入分析页查看详情。
- 快捷操作根据实际能力显示；文章在线编辑未启用时不展示虚假入口。

## 4. 页面状态

- **Loading**：各区独立 skeleton，尺寸稳定。
- **Partial error**：某个摘要失败不阻断待办。
- **Empty**：新站点显示下一步操作，而非全零图表。
- **Stale**：标明聚合更新时间，提供受限的刷新按钮。
- **Permission lost**：立即停止加载并回到认证流程。

## 5. 数据与依赖

- 聚合：`site_daily_stats`。
- 待办：pending comments、draft posts、可选失败任务表。
- 最近内容：文章索引 + `timeline_items`。
- 活动：`activity_events` 或独立审计日志。

后台可见的待审核数量不得进入公开缓存。

## 6. 实现技术要点

- 受保护 Server Component，所有查询在 `requireAdmin()` 后执行。
- 并行查询摘要、待办、评论和活动；独立 Suspense/error 边界。
- 聚合缓存与用户专属数据分开；管理员待办使用短缓存或 no-store。
- 提供手动刷新时使用 Server Action，并限频。
- 快捷入口使用 `ToyButton`，导航项使用链接语义。
- 页面设置 `noindex,nofollow`。

## 7. 可访问性与操作效率

- 指标卡有完整名称和时间范围。
- 最近列表使用语义列表或表格，不用仅靠颜色表达状态。
- 待办数量变化不持续打扰屏幕阅读器。
- 从仪表盘进入处理页时 query 保留目标筛选。

## 8. 验收标准

- 待办、摘要、最近内容和最近评论数据正确。
- 每个摘要都能跳转到对应工作流。
- 部分查询失败时页面仍可处理其他任务。
- 移动端列表可读，键盘操作顺序合理。

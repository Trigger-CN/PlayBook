# 后台时间轴管理设计

## 1. 页面目标

提供时间轴节点的高效创建、编辑、筛选、发布和删除。时间轴是高频、轻量内容，录入流程应比文章编辑更短。

- 路由：`/admin/timeline`，可用抽屉或 `/admin/timeline/[id]` 编辑
- 阶段：Phase 8 第一优先级
- 对应需求：`REQ-ADMIN-004`
- 草稿、版本、自动保存与发布事务统一遵循 [后台内容创作与发布](../modules/14-admin-authoring.md)

## 2. 页面布局设计

### 2.1 桌面端

- 顶部：标题、搜索/类型/年份筛选、“新建节点”。
- 左/主区：按发生时间倒序的紧凑列表或表格。
- 右侧抽屉：新建/编辑表单，保留列表上下文。
- 行字段：时间、类型、标题/摘要、媒体、状态、更新时间、操作。

抽屉宽度保证文本和媒体字段可编辑；需要复杂预览时切换独立页面。

### 2.2 移动端

- 列表改卡片，保留时间、类型、摘要和状态。
- 编辑抽屉占全屏。
- 保存与发布操作固定在可见底部，但需为键盘和安全区留空间。

## 3. 功能设计

### 3.1 查询和筛选

支持类型、年份、状态、关键字，query 可恢复。按 `occurred_at desc, id desc` 排序。

### 3.2 创建/编辑

字段：title（可选）、content、type、occurredAt、image/media、externalUrl、status。

- 内容和发生时间必填。
- 类型限制为已定义枚举。
- 外链校验协议，禁止 `javascript:`。
- 发布时间可与发生时间不同；公开排序始终使用发生时间。
- 表单提供实时卡片预览，但预览不替代校验。

### 3.3 发布和删除

- 保存草稿不出现在公开页。
- 发布触发 `activity_events`、时间轴列表/首页缓存失效。
- 删除前显示关联评论/点赞数量；默认归档或软删除。
- 修改发生时间时提示节点将移动分组位置。

### 3.4 媒体

MVP 单图，后续多媒体。上传完成后才写入节点；删除节点时根据引用策略决定是否删除对象，避免误删共享资源。

## 4. 页面状态

- 列表 loading/empty/error。
- 表单 dirty/saving/saved/error。
- 上传进度、失败和取消。
- 发布冲突：`updated_at` 不一致时阻止覆盖。
- 删除失败保留项目和当前筛选。

## 5. 数据与权限

`timeline_items` 应补充 `status`、`external_url` 等产品所需字段；RLS 公开仅可读 published，管理员可写。互动计数通过聚合批量读取。

## 6. 实现技术要点

- Server Component 读取列表，Client Component 管理抽屉表单。
- Server Action 执行 create/update/archive，统一 `requireAdmin()` 和 Zod。
- 通过 `updated_at` 乐观并发控制。
- 类型到标签/图标/色对的映射来自共享 timeline config，公开页和后台一致。
- 发布后失效 `timeline`、`timeline-item:{id}`、`home`、`stats`。
- 上传使用签名路径和文件限制，客户端不直接拥有任意 bucket 写权限。

## 7. 可访问性与操作效率

- 抽屉正确处理标题、焦点、Escape 和关闭确认。
- 类型选择有文字，不能只显示色块。
- 日期时间输入标明时区；保存后统一为 UTC。
- 列表行操作菜单有明确名称。

## 8. 验收标准

- 管理员可创建、编辑、筛选、发布和归档节点。
- 发生时间、类型、媒体和外链校验正确。
- 发布后公开列表和首页及时更新。
- 并发修改不被静默覆盖，删除会说明互动影响。
- 移动端全屏编辑流程可用。

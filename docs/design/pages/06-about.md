# 关于页面设计

## 1. 页面目标

关于页建立个人身份和长期上下文，说明写作主题、经历、项目、联系方式及站点理念。它是内容页，不是简历系统或营销页。

- 路由：`/about`
- 阶段：MVP
- 数据来源：版本管理的 MDX/配置

## 2. 页面布局设计

### 2.1 桌面端

1. Header。
2. 个人主视觉：姓名、头像/真实形象或代表性作品、短介绍。
3. 正文：我在做什么、关注什么、为什么维护此站。
4. 经历时间线：有限的关键节点，不复制完整时间轴页。
5. 项目与常用链接：可按压项目卡和外链按钮。
6. 联系方式与社交平台。
7. Footer。

主视觉应直接展示人物/作品，不使用纯装饰渐变或营销式分屏卡片。正文保持阅读宽度，项目卡为独立重复项。

### 2.2 移动端

- 头像/主图位于标题附近并保留完整主体。
- 经历和项目单列。
- 联系链接自动换行；邮箱可复制但不强制公开明文地址。

## 3. 功能设计

- 支持 Markdown/MDX 内容和少量受控组件：项目列表、经历条目、链接组。
- 社交链接配置统一复用站点配置，不在页面硬编码多份。
- 项目项包含名称、简介、角色、状态、时间、技术标签、URL、封面和 alt。
- 外链明确新窗口行为；失效链接在发布检查中发现。
- 可展示“最近更新于”，帮助读者判断信息时效。

## 4. 页面状态

- 内容文件缺失属于构建错误，不发布空白页面。
- 个别项目封面缺失使用品牌占位图。
- 联系方式未配置时整段隐藏，不显示空字段。

## 5. 数据结构

```ts
type AboutProject = {
  title: string;
  summary: string;
  role?: string;
  period?: string;
  status?: string;
  tags: string[];
  href?: string;
  cover?: string;
  coverAlt?: string;
};
```

页面主体推荐 `content/pages/about.mdx`，站点身份和链接来自 `site.config.ts`。

## 6. 实现技术要点

- 静态生成；内容变化随部署更新。
- 复用 MDX 管线，但组件白名单可与文章不同。
- metadata 使用个人/站点名称、简介和清晰头像或品牌图。
- 对外邮箱可通过表单、编码展示或专用公开地址降低采集风险。
- 图片使用 `next/image`，头像和项目封面分别定义固定比例。
- 项目卡使用链接语义和按压状态，不在卡内嵌套第二个链接。

## 7. 可访问性与隐私

- 头像有真实替代文本，装饰贴纸隐藏。
- 经历时间线不只靠位置或颜色表达先后。
- 不公开私人住址、电话、非公开经历或敏感元数据。
- 所有联系操作键盘可达，复制成功使用 `aria-live` 提示。

## 8. 验收标准

- 页面清楚回答“是谁、在做什么、关注什么、如何联系”。
- 项目和经历内容在桌面/移动端可扫描。
- 内容、配置、社交链接无重复数据源。
- metadata、图片 alt、外链安全属性正确。

# 后台分析页设计

## 1. 页面目标

向管理员提供比公开统计更详细的内容表现、访问趋势和系统健康信息，用于内容决策和发现异常，不用于跨站追踪用户。

- 路由：`/admin/analytics`
- 阶段：Phase 8
- 对应需求：`REQ-ADMIN-005`、`REQ-STAT-*`

## 2. 页面布局设计

### 2.1 桌面端

1. 时间范围、粒度和刷新时间工具栏。
2. 核心指标：有效浏览、点赞、公开/待审评论、发布数。
3. 趋势图：浏览和互动分开，避免双轴误导。
4. 内容排行：文章、时间轴。
5. 来源与设备摘要（仅聚合且达到最小样本）。
6. 活动/异常：流量尖峰、聚合任务失败、接口限流事件。

页面是操作型分析面板，使用紧凑表格和图表，不使用大型宣传数值。

### 2.2 移动端

- 时间范围折叠为菜单。
- 图表纵向排列，固定高度。
- 排行表转换为列表，保留排名、标题、指标和趋势。

## 3. 功能设计

- 时间范围：7/30/90/365 天和自定义（后续）。
- 粒度：日；长范围可按周/月聚合。
- 指标 tooltip/说明明确去重口径。
- 内容排行支持按浏览、点赞、评论切换。
- 导出聚合 CSV 为后续能力；不得导出访客标识。
- 异常标记只辅助调查，不自动认定攻击或内容质量。

## 4. 页面状态

- 数据尚未聚合：提示任务状态和可重试入口。
- 小样本：隐藏来源/设备细分。
- 部分图表失败：其他指标保持可用。
- 无事件：展示配置/发布下一步。
- 自定义范围非法：字段错误，不执行查询。

## 5. 数据与权限

使用 `site_daily_stats`、内容聚合视图、`activity_events` 和有限的安全事件聚合。原始 `page_views` 只由受控服务端查询，默认不下发逐条记录。

## 6. 实现技术要点

- 受保护 Server Component 获取已聚合数据。
- Recharts 等图表按需动态加载，服务端先输出文字摘要。
- 大范围查询调用数据库 RPC/物化视图，不把所有事件传到 Node 聚合。
- 时间参数按站点时区解释，数据库存 UTC。
- 分析缓存 5 至 15 分钟；管理员刷新需限频。
- 导出任务使用服务端生成、短期签名链接和审计。

## 7. 可访问性与隐私

- 每个图表提供等价文字和数据表。
- 序列使用颜色、线型和标签共同区分。
- 来源、地区、设备只展示达到阈值的聚合；不展示单访客轨迹。
- 管理页面 noindex，查询和导出都要求权限。

## 8. 验收标准

- 时间范围和指标切换影响所有相关区域。
- 指标与聚合表及公开统计口径可解释地一致。
- 大范围查询不扫描/下发无界原始事件。
- 小样本隐私保护和异常状态生效。
- 图表在桌面、移动和屏幕阅读器中均可理解。

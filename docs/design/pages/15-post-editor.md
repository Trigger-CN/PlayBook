# 文章书写页设计

## 1. 页面目标

文章书写页为管理员提供从草稿到发布的完整写作工作流：编辑正文与元数据、实时预览、发布前校验、保存草稿与发布。它把原本分散在本地文件流程中的写作动作收拢到受控的在线编辑器，并复用内容管线、媒体、SEO 与缓存模块的既有契约。对应 `REQ-ADMIN-006/007`。

- 路由：`/admin/posts/new`、`/admin/posts/[id]/edit`
- 阶段：Phase 8 后续（数据库正文源启用后）；文件型 MVP 为只读索引，本文档描述在线编辑启用后的目标设计
- 主要用户：管理员
- 主要任务：写作、设置元数据、预览、校验、保存草稿、发布

## 2. 页面布局设计

### 2.1 桌面端

1. **顶部工具条（sticky）**：返回列表、文章标题、保存状态、预览、发布主按钮。
2. **三栏工作区**：
   - 主区：标题、摘要、正文编辑器（Markdown 源码 + 编辑 / 预览 / 检查 三面板）与底部字数状态。
   - 右侧设置栏：网址标识（只读）、封面与 alt、标签、分类、发布日期、精选、状态。
   - 预览与检查在**主区内切换**，不是独立的第三栏 —— 一栏没做完的抽屉（焦点陷阱、滚动锁定）比在主区内切换更糟。
3. **编辑器工具栏**：插入行内公式、公式块、mermaid 图表、代码块；全部使用立体小按钮。
4. **检查面板**：结构诊断清单，点一条跳回对应行。
5. **底部操作**：保存草稿与发布在窄屏吸附于可见区域。

主区最小宽度 520px，设置栏 300–340px；宽度不足时设置栏折叠为抽屉。发布与保存按钮同宽结构，390px 不溢出。

### 2.2 移动端

- 单列布局：编辑器在上，设置区堆叠在下。
- 工具栏横向滚动，保留触控面积。
- 保存/发布在窄屏跟随正文，不用滚回顶部。
- 预览为只读渲染，不在预览层直接编辑。
### 2.3 正文编辑器的实际形态（决策 D-32）

编辑器是 **CodeMirror 6** 源码编辑器，不是富文本画布。理由：正文的权威格式是 Markdown 源码，而「文档模型 + 双向序列化」类编辑器把 Markdown 当导入导出格式，往返一次就会丢公式、图表、代码块语言标记与表格对齐。

- **编辑**：行号、括号匹配、撤销、搜索；结构问题直接标在行内（波浪线）。
- **预览**：停手 450ms 后调 Server Action，用与公开文章页**同一个 processor** 渲染。
- **检查**：六类规则 —— 围栏未闭合、`$$` 未配对、链接缺右括号、图片缺 alt、空图表、h4–h6 与标题跳级。

提交仍走隐藏字段 `name="body"`：CodeMirror 是 `contenteditable`，不会自己进 `FormData`；`body` 保持受控 state，以满足「失败不丢稿」。


### 3.1 字段与内容模型

字段与内容管线 frontmatter 对齐：`title`、`slug`、`summary`、`cover`、`coverAlt`、`publishedAt`、`updatedAt`、`tags`、`category`、`draft`、`featured`、`body`。

- `body` 为 **Markdown（GFM）**，支持 `$行内公式$`、`$$块级公式$$` 与 ```mermaid 图表围栏，见决策 D-32。
- 正文允许内嵌排版类 HTML；`script`/`iframe`/`on*` 属性在渲染管线中被剔除。
- 存在 `cover` 时 `coverAlt` 必填。
- `summary` 来自人工输入，不由正文自动截断。

### 3.2 编辑与自动保存

- 输入即置 dirty；自动保存仅保存草稿，间隔 15–30 秒或失焦触发，不自动发布。
- 自动保存写入草稿版本，不产生公开可见内容。
- 会话过期或网络失败时保留本地临时草稿（localStorage），恢复后提示合并。
- 保存状态在工具条可见：dirty → saving → saved / save failed。

### 3.3 实时预览

- 预览在与公开文章页**同**的白名单管线下渲染（同一份 `renderMarkdownToHtml`）；预览不进入公共缓存。
- 预览走 Server Action，不单独开路由：天然继承会话，不需要 token，也不会把未发布正文暴露在任何可被抓取的 URL 上。
- 预览失败不阻断编辑，只显示错误说明。

### 3.4 发布前校验

- 必填：`title`、`slug`、`summary`、发布日期（或选择立即发布）。
- `cover` 存在则 `coverAlt` 必填。
- `slug` 由服务端生成，不校验格式也不允许编辑（决策 D-31）。
- 内部链接存在、外部链接协议白名单（http/https/mailto）。
- 正文能通过 Markdown 渲染（与公开文章页同一 processor）。
- 校验失败聚焦问题摘要并逐条关联字段。

### 3.5 发布

- 发布动作明确列出影响范围：文章详情、列表、首页、标签/分类、sitemap、RSS。
- 发布以事务协调正文写入、`activity_events` 记录和缓存 tag 失效。
- 不允许半完成状态：正文未保存成功不得标记为已发布。
- 发布成功提供“查看公开页”入口。

### 3.6 并发与版本

- 使用 `updated_at`/version 乐观锁；保存时发现版本变化则阻止覆盖并提示对比。
- 多人编辑同一文章返回冲突，要求重新加载或合并，禁止静默覆盖。

## 4. 页面状态

- **Loading**：编辑器骨架与字段占位，尺寸稳定。
- **Dirty / Saving / Saved / Save failed**：工具条状态，配合礼貌级 `aria-live`。
- **Validation failed**：问题摘要 + 字段错误，保留输入。
- **Publishing**：锁定发布按钮，保留内容并显示进度。
- **Conflict**：版本冲突对话框，初始焦点在“取消/重新加载”。
- **Session expired**：保留本地草稿并提示重新登录。
- **Permission denied**：非管理员返回 403，不渲染编辑器。

## 5. 数据与依赖

- 正文来源：在线编辑启用后为数据库 `posts`；文件型模式下为只读索引。
- 媒体：封面与正文图依赖媒体模块，上传先入草稿路径，引用确认后转正。
- 依赖模块：内容管线、媒体资源、SEO/分享/RSS、认证安全、数据获取与缓存状态。
- 草稿版本、自动保存、发布事务与失效的完整契约见 [后台内容创作与发布](../modules/14-admin-authoring.md)。

## 6. 实现技术要点

- 受保护 Server Component 外壳 + Client Component 编辑器；`requireAdmin()` 在页面、Action、Handler 统一调用。
- 表单使用 React Hook Form + Zod，Server Action 二次校验。
- 正文渲染统一走 `lib/content/markdown.ts`（**不再是 MDX**）：`remark-parse` → `remark-gfm` + `remark-math` → `remark-rehype` → `rehype-raw` → 安全剔除 → mermaid 围栏重写 → `rehype-pretty-code` → `rehype-katex` → `rehype-stringify`。完整理由与插件顺序约束见决策 D-32。
- 预览与公开页共用同一个 processor，避免「预览里好好的、发布后坏了」。
- 自动保存走独立 Server Action，限频并写草稿版本。
- Mermaid 在浏览器端动态 `import()` 并渲染；KaTeX 在服务端渲染成 HTML，CSS 在根布局引入。
- 页面 `noindex,nofollow`。

## 7. 可访问性与安全

- 编辑器容器带 `aria-label`，诊断清单可键盘访问。
- 工具栏按钮用 `ToyButton`（外层唯一交互根），有可访问名称。
- 预览面板是只读渲染，不是唯一编辑方式 —— 编辑面板始终可切换回来。
- 正文内嵌 HTML 在服务端被剔除非安全标签与 `on*` 属性；`href`/`src` 限协议白名单。
- 上传与正文均服务端校验。

## 8. 验收标准

- 可创建、编辑、保存草稿、预览、发布与归档文章。
- 发布前校验覆盖 frontmatter、Markdown 渲染、图片、链接与 slug。
- 保存/发布失败不丢失正文；并发编辑不静默覆盖。
- 正文中的 `$公式$`、`$$公式块$$` 与 ```mermaid 围栏在预览与公开页都能渲染。
- 发布后首页、列表、详情、sitemap/RSS 正确失效。
- 390px 下编辑器、工具栏与操作按钮无页面级溢出。

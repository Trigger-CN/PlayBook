# 首页设计

## 1. 页面目标

首页是个人内容站的总入口，首屏建立“可交互数字玩具盒”的视觉识别，随后让访客快速进入文章、时间轴、关于页和外部链接，并用聚合数据说明站点持续活跃。对应 `REQ-HOME-001` 至 `REQ-HOME-021`。

- 路由：`/`
- 阶段：MVP
- 主要用户：首次访客、回访读者
- 主要任务：理解站点是谁、发现最新内容、进入目标栏目、切换主题

## 2. 页面布局设计

### 2.1 桌面端

页面内容宽度建议 `1180px`，按以下顺序形成纵向信息流：

1. **全站 Header**：品牌标记、文章/时间轴/关于导航、主题开关。
2. **Hero**：左侧个人简介、价值陈述和“开始阅读”主 CTA；右侧为不抢夺阅读的矢量互动场景。
3. **快捷跳转栏**：文章、时间轴、项目、关于、GitHub、RSS 等 4 至 8 个立体按钮。
4. **站点统计摘要**：总文章数、总浏览量、总点赞、总评论、最近更新时间。
5. **最近文章**：3 至 6 张可按压文章卡，展示缩略图、标题、摘要、时间与标签。
6. **最近时间轴**：5 至 10 个节点，桌面端可与文章区构成双栏。
7. **最近活跃**：发布、更新和互动里程碑，不展示敏感访客信息。
8. **Footer**：版权、RSS、社交链接、隐私说明。

Hero 占首屏主要区域，但必须在常见桌面视口底部露出下一模块提示。首页不是营销落地页，不放功能宣传卡和冗长说明。

### 2.2 移动端

- Header 保留品牌和主题开关，栏目导航放入菜单或在后续内容提供入口。
- Hero 视觉场景置于文案上方，主标题按自然语义换行，不使用按视口缩放字体。
- CTA 允许两列或自动换行，最小触控高度 44px。
- 快捷入口使用两列网格；不得造成横向页面滚动。
- 统计块使用两列，最后一个可独占一列。
- 最近文章与时间轴改为单列，完整卡片均可点击。

## 3. 功能设计

### 3.1 Hero

- 展示姓名/站点名、一句话定位、简短介绍和主视觉。
- 主 CTA 指向 `/posts`，次 CTA 可指向 `/about` 或重点项目。
- 社交链接需标明外链行为，外部链接使用 `rel="noopener noreferrer"`。
- 大型 Rive/Lottie 场景延迟加载；加载前使用稳定尺寸的静态占位。

### 3.2 快捷入口

- 数据字段：`title`、`href`、`icon`、`description`、`order`、`external`、`enabled`。
- MVP 从配置文件读取；仅渲染启用项并按 `order` 排序。
- 每个入口使用立体按钮结构，支持 hover、active、focus-visible。

### 3.3 内容聚合

- 最近文章只读取已发布且非未来时间内容。
- 最近时间轴按 `occurred_at desc` 排序。
- 首页不加载完整正文，只加载卡片所需字段。
- 卡片点击区必须是一个语义正确的链接，不在链接中嵌套按钮。

### 3.4 统计与活跃

- 统计优先读取 `site_daily_stats` 或缓存后的聚合结果。
- 最近活跃读取公开、脱敏后的 `activity_events`。
- 动态统计失败时仍渲染静态首页内容；统计模块显示轻量不可用状态。

### 3.5 主题切换

- 首次访问参考 `prefers-color-scheme`；手动选择保存到 localStorage 或 cookie。
- 切换即时更新背景、按钮、卡片、统计和时间轴，不刷新页面。
- 开关使用 `aria-pressed` 和可理解的 `aria-label`。

## 4. 页面状态

- **Loading**：静态框架立即呈现，动态统计使用固定尺寸 skeleton。
- **Empty**：无文章时展示站点介绍和“内容准备中”；无时间轴时隐藏对应标题或显示简短空状态。
- **Partial error**：单个聚合模块失败不能阻断其他模块。
- **Offline/stale**：可以展示缓存内容，并避免伪造“实时”标签。
- **Reduced motion**：停止场景循环动画和过渡，保留静态构图及按压状态差异。

## 5. 数据与依赖

| 区域 | 数据来源 | 最少字段 |
| --- | --- | --- |
| Hero | 站点配置 | name、bio、socialLinks、heroAsset |
| 快捷入口 | 配置文件 | title、href、icon、order、enabled |
| 最近文章 | MDX 索引/文章仓库 | slug、title、summary、cover、publishedAt、tags |
| 最近时间轴 | `timeline_items` | id、title、content、type、image_url、occurred_at |
| 统计 | `site_daily_stats` 聚合 | views、posts、timeline、likes、comments |
| 活跃 | `activity_events` | event_type、target、title、created_at |

依赖模块：视觉主题、站点外壳、内容管线、时间轴、统计活跃度、媒体资源。

## 6. 实现技术要点

- `app/(site)/page.tsx` 使用 Server Component。
- 静态 Hero、快捷配置、最近文章可静态生成；时间轴和统计采用 ISR 或带 tag 的服务端缓存。
- 主题开关、互动场景单独使用 Client Component，避免整页客户端化。
- 使用 `Promise.all` 并行读取文章、时间轴和统计；需要局部容错时使用独立 Suspense 边界。
- 首页缓存建议 5 至 15 分钟；发布内容后通过 `revalidateTag('home')` 主动失效。
- 图片使用 `next/image` 和明确 `sizes`；首屏关键图可 priority，其他资源懒加载。
- 首页 metadata 使用站点默认标题、描述、canonical 和 OG 图。

## 7. 可访问性与响应式

- 页面只保留一个 `h1`，各模块使用顺序正确的 `h2`。
- 跳过导航链接指向主内容。
- 所有纯装饰图标 `aria-hidden="true"`；主视觉若传递信息需替代文本。
- 键盘焦点不能被卡片 overflow 裁剪。
- 390px、768px、1440px 均需检查无横向溢出、文字遮挡和布局跳动。

## 8. 验收标准

- 首屏明确展示站点身份、主 CTA、主题开关和视觉主题。
- 首页展示 3 至 6 篇文章、5 至 10 个时间轴节点或对应空状态。
- 快捷入口可由配置增删排序，外链行为正确。
- 统计读取聚合数据，失败不影响静态内容。
- 日夜主题即时切换并持久化。
- 桌面和 390px 移动端无溢出，键盘可到达所有入口。

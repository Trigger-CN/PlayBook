# 公开统计页设计

## 1. 页面目标

公开统计页展示站点长期活跃程度、内容规模和阅读趋势，增强个人站的持续感，但不暴露单个访客或后台运营细节。

- 路由：`/stats`
- 阶段：增强功能；首页摘要为 MVP
- 对应需求：`REQ-STAT-003` 至 `REQ-STAT-011`

## 2. 页面布局设计

### 2.1 桌面端

1. Header、标题和数据更新时间。
2. 核心指标带：总浏览、文章、时间轴、点赞、公开评论。
3. 趋势区：近 30/90/365 天浏览和互动趋势。
4. 内容分布：按标签/分类/时间轴类型汇总。
5. 热门内容：文章和时间轴排行。
6. 活跃记录：发布、更新、公开互动里程碑。
7. 指标说明和隐私说明。

图表是分析工具，不放入装饰卡套卡；使用全宽区带和明确坐标。颜色与主题系统一致，但每个序列不能只靠颜色区分。

### 2.2 移动端

- 指标两列。
- 图表容器固定高度，减少序列或允许内部横向浏览，页面不横向溢出。
- 排行榜使用紧凑列表，不做宽表格。
- 时间范围使用分段控制或菜单。

## 3. 功能设计

- 时间范围：30 天、90 天、1 年、全部；写入 query。
- 指标来自每日聚合，不直接扫描原始 `page_views`。
- 热门内容按有效浏览、点赞、评论的明确规则排名。
- 最近活跃只展示公开内容事件和聚合里程碑，不展示访客标识。
- 指标定义、统计口径、更新时间可见，避免误读。
- 数据不足时不绘制误导性趋势线，使用“数据积累中”。

## 4. 页面状态

- **Loading**：Server Component 优先输出；客户端图表使用固定容器占位。
- **Empty**：没有足够日期数据时展示累计指标和积累说明。
- **Partial**：趋势失败时核心累计指标仍可用。
- **Stale**：标明最后聚合时间，不宣称实时。
- **Invalid range**：回退 30 天并规范化 URL。

## 5. 数据与口径

核心表：`site_daily_stats`、`activity_events`，热门内容使用单独聚合查询或物化视图。

```ts
type PublicStats = {
  totals: { views: number; posts: number; timeline: number; likes: number; comments: number };
  series: Array<{ date: string; views: number; likes: number; comments: number }>;
  popularPosts: RankedContent[];
  popularTimeline: RankedContent[];
  updatedAt: string;
};
```

公开评论数只统计 approved 或产品定义的公开口径；浏览量使用去重后的有效事件。

## 6. 实现技术要点

- 页面使用 Server Component + ISR，缓存 15 分钟到 1 小时。
- 图表组件延迟加载，仅将已聚合序列传给客户端。
- Supabase 查询限定日期范围和字段，必要时使用 RPC/数据库视图。
- 聚合任务可由 Vercel Cron 或 Supabase Scheduled Function 执行，要求幂等 upsert。
- query 范围白名单校验；对过大数据集服务端下采样。
- metadata 描述公开统计口径；是否索引由站点策略决定。

## 7. 可访问性与隐私

- 每张图表提供标题、文字摘要和可访问数据表/列表。
- 图形使用颜色、线型和标签共同区分。
- 不公开 IP/UA hash、referrer 明细、单访客轨迹、待审核评论数。
- 小样本来源数据应聚合或隐藏，降低再识别风险。

## 8. 验收标准

- 累计指标与每日聚合一致。
- 时间范围可恢复并正确影响全部图表。
- 数据口径、最后更新时间和空数据状态清晰。
- 公开页面不泄漏原始事件或访客标识。
- 移动端图表和排行榜可读，键盘与屏幕阅读器可获得等价信息。

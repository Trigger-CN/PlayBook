# 登录页设计

## 1. 页面目标

登录页为管理员提供唯一认证入口，只呈现认证所需信息，防止开放重定向、会话泄漏和信息过度暴露。对应 `REQ-ADMIN-001`、`REQ-SEC-005/006`。

- 路由：`/admin/login`
- 阶段：Phase 8
- 主要用户：管理员
- 主要任务：提交邮箱与口令、处理失败与限流、安全返回目标后台路径

## 2. 页面布局设计

### 2.1 桌面端

1. 居中登录卡（最大 420px）：品牌标记、标题、简短说明。
2. 主登录方式：管理员邮箱 + 口令两个输入字段，一个「登录」按钮。
3. 口令由服务端环境变量提供，页面不提供「找回口令」入口。
4. 主题开关（与全站一致）。
5. 安全说明：会话时长、失败限流、未授权拒绝。
6. 消息区：错误提示（`role="status"` 与礼貌级 `aria-live`）。

不展示任何后台页面信息、统计数据或导航。

### 2.2 移动端

- 卡片单列占满宽度，内边距收紧。
- 触控目标 ≥44px；软键盘弹出不遮挡提交按钮。

## 3. 功能设计

### 3.1 登录方式

- **账号口令**：邮箱必须落在 `ADMIN_EMAIL` 白名单内，口令必须等于 `INTERACTION_HASH_SALT`。
- 口令只做服务端比较，数据库里既无口令也无口令哈希。
- 两项判断都算完再合并结果，不因「邮箱不在名单」提前返回。
- 失败文案统一为「邮箱或口令不正确。」，不区分是账号错还是口令错。
- 同一邮箱 5 分钟内最多 5 次尝试，超出进入临时限流。

### 3.2 重定向安全

- `next` 参数仅允许同源、白名单后台路径；非法值回退 `/admin`。
- 登录成功默认跳转 `/admin`。
- 防止开放重定向与参数注入。

### 3.3 权限结果

- 邮箱或口令任一不符：返回统一失败文案，不进入后台。
- 未登录访问后台：跳转 `/admin/login?next=...`。

### 3.4 会话

- 会话由自建库的 `admin_sessions` 管理，cookie 采用 HttpOnly / Secure / SameSite=lax。
- 会话 7 天有效，库中只存哈希，可单独撤销。
- 退出通过 POST/Server Action，不使用可预取 GET。
- 会话过期提示重新认证，保留未提交草稿（可行时）。

## 4. 页面状态

- **Idle**：表单可编辑。
- **Submitting**：锁定提交，保持按钮宽度，`aria-busy`。
- **Denied**：统一失败文案，两个字段都标 `aria-invalid`。
- **Rate limited**：提示需等待的秒数。
- **Unavailable**：缺 `DATABASE_URL` 或环境变量时说明具体缺什么。
- **Checking session**：避免先渲染后台再闪回登录。

## 5. 数据与安全边界

- 身份来源为环境变量 `ADMIN_EMAIL`（逗号分隔白名单）与 `INTERACTION_HASH_SALT`（登录口令），不落库。
- 客户端只使用 anon key；service role 永不下发。
- 登录成功与失败进入审计，不记录口令或会话明文。

## 6. 实现技术要点

- `app/admin/(auth)/login/page.tsx` 渲染，`noindex,nofollow`。
- Server Action 处理登录、会话写入与重定向白名单。
- 两个输入字段受控 —— React 19 在 form action 提交后重置非受控字段，口令输错一次就会连同邮箱一起被清空。
- `middleware.ts` 只检查会话 cookie 是否存在，最终授权在服务端函数校验。
- 登录成功只回跳同源后台路径。

## 7. 可访问性

- 完整 label 与 autocomplete（`email`、`current-password`）。
- 错误关联字段，并通过 aria-live 宣布。
- 键盘可完成全部流程；错误后焦点移到首个错误字段。

## 8. 验收标准

- 未登录或口令错误无法进入任一后台页面或接口。
- 重定向仅限同源白名单路径。
- 口令错误、限流与环境变量缺失三种状态文案清晰且互不泄漏。
- 不暴露 service role、敏感统计或未授权内容。

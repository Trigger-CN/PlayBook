# 登录页设计

## 1. 页面目标

登录页为管理员提供唯一认证入口，只呈现认证所需信息，防止开放重定向、会话泄漏和信息过度暴露。对应 `REQ-ADMIN-001`、`REQ-SEC-005/006`。

- 路由：`/admin/login`
- 阶段：Phase 8
- 主要用户：管理员
- 主要任务：发起登录、处理链接过期/失败、安全返回目标后台路径

## 2. 页面布局设计

### 2.1 桌面端

1. 居中登录卡（最大 420px）：品牌标记、标题、简短说明。
2. 主登录方式：邮箱输入 + “发送魔法链接”。
3. 备选方式：受控 OAuth 提供商按钮。
4. 主题开关（与全站一致）。
5. 安全说明：会话来源、失败记录、未授权拒绝。
6. 消息区：错误/成功提示（`role="alert"` 或礼貌级 `aria-live`）。

不展示任何后台页面信息、统计数据或导航。

### 2.2 移动端

- 卡片单列占满宽度，内边距收紧。
- 触控目标 ≥44px；软键盘弹出不遮挡提交按钮。

## 3. 功能设计

### 3.1 登录方式

- **魔法链接**：输入邮箱 → 发送一次性链接 → 提示有效期；链接失效可重发。
- **OAuth**：受控提供商；回调后校验管理员角色。
- 不自建密码存储。

### 3.2 重定向安全

- `next` 参数仅允许同源、白名单后台路径；非法值回退 `/admin`。
- 登录成功默认跳转 `/admin`。
- 防止开放重定向与参数注入。

### 3.3 权限结果

- 登录成功但非管理员：返回 403 提示，不进入后台。
- 未登录访问后台：跳转 `/admin/login?next=...`。

### 3.4 会话

- 会话由 Supabase Auth 管理；cookie 采用 HttpOnly/Secure/SameSite 合理配置。
- 退出通过 POST/Server Action，不使用可预取 GET。
- 会话过期提示重新认证，保留未提交草稿（可行时）。

## 4. 页面状态

- **Idle**：表单可编辑。
- **Sending**：锁定提交，保持按钮宽度，`aria-busy`。
- **Sent**：提示链接已发送及有效期。
- **Invalid/expired link**：清楚说明并允许重发。
- **Forbidden**：无权限提示，不泄漏资源内容。
- **Checking session**：避免先渲染后台再闪回登录。

## 5. 数据与安全边界

- 身份来源 Supabase `auth.users`；管理员授权来自环境 allowlist 或角色表。
- 客户端只使用 anon key；service role 永不下发。
- 登录与失败记录进入审计，不记录明文 token。

## 6. 实现技术要点

- `app/admin/login/page.tsx` 渲染，`noindex,nofollow`。
- Server Action 处理登录与重定向白名单。
- `middleware.ts` 刷新会话 cookie，最终授权在服务端函数校验。
- 登录成功只回跳同源后台路径。

## 7. 可访问性

- 完整 label 与 autocomplete（`email`、`one-time-code`）。
- 错误关联字段，并通过 aria-live 宣布。
- 键盘可完成全部流程；错误后焦点移到首个错误字段。

## 8. 验收标准

- 未登录与非管理员无法进入任一后台页面或接口。
- 重定向仅限同源白名单路径。
- 链接过期、发送失败与无权限状态清晰。
- 不暴露 service role、敏感统计或未授权内容。

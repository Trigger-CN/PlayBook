# 后台设置页设计

## 1. 页面目标

集中管理站点身份、快捷链接、公开联系方式、主题选项和数据维护能力。设置按领域分区独立保存，避免一个巨大表单产生不明确副作用。

- 路由：`/admin/settings`
- 阶段：后续；MVP 对应内容保存在配置文件

## 2. 页面布局设计

### 2.1 桌面端

左侧设置导航，右侧分区表单：

1. 站点信息：名称、描述、站点 URL、时区。
2. 个人资料：简介、头像、公开联系方式、社交链接。
3. 快捷入口：新增、编辑、启停、排序。
4. 视觉主题：默认主题、允许跟随系统、品牌色预览。
5. 内容设置：默认分类、评论开关/长度、审核策略。
6. 数据管理：导出、备份状态；危险操作独立区域。

每个分区有自己的保存按钮、dirty 状态和权限说明。危险区与普通设置视觉和空间隔离。

### 2.2 移动端

- 左侧导航变为设置类别菜单。
- 排序使用上下移动按钮或可访问拖拽替代，不依赖精细拖动。
- 颜色预览和表单单列。

## 3. 功能设计

### 3.1 站点和个人信息

- URL、邮箱、外链服务端校验。
- 时区从 IANA 列表选择，影响统计显示和发布日期输入。
- 头像/品牌图通过媒体模块选择。

### 3.2 快捷入口

字段与首页配置一致：title、href、icon、description、order、external、enabled。排序保存为稳定数值；外链自动建议 external，但允许确认。

### 3.3 主题

- 只配置已支持 token，不提供任意 CSS 注入。
- 修改时同时预览日间/晚间以及按钮面/底座色对。
- 保存前检查基础对比度和必要 token 完整性。

### 3.4 评论与内容策略

- 评论是否开放、最大长度、是否总需审核。
- 策略变化只影响未来提交，除非明确执行批量迁移。

### 3.5 导出与危险操作

- 导出为异步任务并记录审计。
- 不在同页提供“一键清空所有数据”。确需删除时使用独立确认流程、重新认证和冷静期。

## 4. 页面状态

- 分区 loading/save/saved/error 独立。
- 离开 dirty 分区前提示。
- 保存冲突使用版本字段，提示重新加载。
- 上传、导出显示进度和最终结果。
- 无后台设置存储时清楚标记配置文件为真实来源，只读展示。

## 5. 数据与权限

建议新增 `site_settings`（受控 JSON 或字段化表）、`quick_links`、管理员审计日志。敏感密钥只通过部署环境配置，绝不显示或写入通用设置表。

## 6. 实现技术要点

- 每个设置区独立 Server Action + Zod schema。
- 使用版本号/updated_at 乐观锁。
- 快捷链接排序在事务中更新，保证唯一稳定顺序。
- 主题配置生成受控 CSS variables，不拼接任意样式字符串。
- 保存后按影响范围失效 `site-config`、`home`、`layout` 等 tag。
- 导出使用后台任务和短期签名下载 URL。

## 7. 可访问性与安全

- 每个设置区有 fieldset/legend 或明确标题。
- 错误摘要链接到具体字段。
- 拖拽排序提供键盘按钮与位置播报。
- 危险操作要求重新认证、明确目标和不可逆说明。
- 密钥、service role 和私密联系方式不进入客户端响应。

## 8. 验收标准

- 各分区独立保存且 dirty 状态准确。
- 配置文件模式和数据库设置模式来源清晰。
- 快捷入口排序/启停能正确影响首页。
- 主题配置不能注入任意 CSS，且日夜色对完整。
- 缓存按影响范围失效，敏感操作有权限和审计。

# 时间轴详情页设计

## 1. 页面目标

展示单个时间轴节点的完整内容、图片、外部链接和互动，使列表中的碎片记录拥有可分享、可评论的稳定地址。

- 路由：`/timeline/[id]`
- 阶段：MVP
- 对应需求：`REQ-TL-003` 至 `REQ-TL-008`、`REQ-INT-*`

## 2. 页面布局设计

### 2.1 桌面端

1. Header、返回时间轴和面包屑。
2. 节点头部：类型、发生时间、标题。
3. 主体卡片：完整文本、图片画廊、可选外部链接。
4. 上一条/下一条节点导航。
5. 互动摘要：浏览、点赞、评论。
6. 已审核评论与评论表单。
7. Footer。

主体使用可按压卡片语言，但正文区域本身不因点击整体位移。只有明确的导航卡、点赞、评论和外链按钮使用按压反馈。

### 2.2 移动端

- 返回入口置于标题前。
- 元信息自然换行，图片单列全宽。
- 上一条/下一条纵向排列。
- 点赞、评论、外链按钮自动换行且保留底座。

## 3. 功能设计

- 按 `id` 查询公开节点；不存在或未发布返回 404。
- 展示 `occurred_at`，可同时展示明显不同的更新时间。
- 文本 MVP 只支持安全纯文本换行和自动链接；若未来支持 Markdown，必须走白名单渲染。
- 图片支持 0 至多张；MVP 数据表只有 `image_url` 时按单图处理，扩展后改关联表。
- 外链显示域名和新窗口标记，使用安全 `rel`。
- 点赞、评论、浏览量使用统一目标：`target_type=timeline_item`、`target_id=id`。
- 上一条/下一条按 `occurred_at` 和 `id` 稳定查询，不按创建时间。

## 4. 页面状态

- **Not found**：不存在、草稿或无权限统一返回 404。
- **Media error**：保留说明和占位，不阻断文本。
- **Interaction error**：节点主体保持可读，互动区局部重试。
- **Comment pending**：提交后提示待审核，不插入公开列表。
- **No adjacent item**：隐藏对应方向，避免禁用空按钮。

## 5. 数据与依赖

读取 `timeline_items` 完整公开字段、互动聚合计数、approved 评论和相邻节点摘要。依赖时间轴领域、媒体、点赞、评论、浏览量和 SEO 模块。

## 6. 实现技术要点

- `app/(site)/timeline/[id]/page.tsx` 使用 Server Component。
- UUID/ID 在查询前校验格式，避免无效数据库请求。
- 详情页使用 ISR；节点更新后失效 `timeline-item:{id}`、`timeline`、`home`。
- metadata 由标题、内容摘要、类型和首图生成；canonical 使用稳定详情 URL。
- JSON-LD 可使用 `SocialMediaPosting` 或较通用的 `Article`，缺字段时不强行输出。
- 点赞、评论、浏览记录为客户端岛；主体 HTML 服务端生成。
- 相邻节点查询使用复合排序与索引 `(occurred_at, id)`。

## 7. 可访问性与安全

- `<time>` 提供 ISO datetime。
- 图片 alt 来自节点媒体信息；缺少描述时由管理员补充，装饰图才可空 alt。
- 外链按钮名称包含目标或域名。
- 评论表单完整 label、错误关联和提交状态。
- 公开响应不包含 IP hash、邮箱 hash、visitor_id 或后台状态字段。

## 8. 验收标准

- 节点完整内容、类型、日期、媒体和外链正确显示。
- 上一条/下一条顺序稳定。
- 点赞、评论和浏览量使用统一目标模型。
- 不存在节点返回 404，互动失败不影响正文。
- metadata、canonical、移动布局和键盘操作正确。
